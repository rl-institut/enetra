{% comment %} The desired behaviour is for the select to show that no selection is made, potentially to require the selection, but also not show the "null" value as selectable item. Django by default does not pass "required" to the select item, if the choices do not contain an empty selection. Native selects would simply select the first option, if no option is "selected". To properly require a select without an empty selection choice, but not preselect some choice we need to pass required to the component itself this is kinda tricky, but possible. :attrs="{'foo':'bar'}" expands the attrs, so rendering {{attrs}} would yield foo='bar' as well. this behaviour can be used to pass a dynamic attribute to the component. (NOTE: required='false' would not work, since the rhs is not evaluated. for the "requiredness" of an input/select the only requirement is "required" tag on the input) therefore the following works: if the field is required the attrs are expaned with {'required':'true'} if the field is not required the attrs are expanded with {'not-required':'true'} the tag not-required='true' does nothing but :attrs="{'{{field.field.required|yesno:'required,not-required'}}':'true'}" with alpine.js and x-data scope a more verbose x-bind::required="{{field.field.required|yesno:'true,false'}}" is also possible which renders required based on the evaluation of true/false {% endcomment %} {% else %} {% endif %}
